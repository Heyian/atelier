# Skill hygiene

Every skill you install carries a description Claude reads to decide
whether it applies to what you just wrote. The more active skills pile up,
the more descriptions compete for the same sentence — and that's where
things start going wrong. Skill hygiene is the upkeep that keeps that
matching sharp.

## One skill per role, not per task

The right grain is the role or the job that keeps coming back — not each
one-off task. One "sales" skill that covers everything your sales team
does beats ten skills, one per type of email you send. A skill built
around a single narrow task ends up adding more noise than help: it waits
its turn to answer one specific phrase, and most skills built that way
only ever fire once.

## Two descriptions, one sentence

When two skills could both answer what you just wrote, Claude has to
guess which one you meant — and it sometimes guesses wrong. The fix isn't
picking a winner and dropping the other: merge the two into one broader
skill, or sharpen one description so it no longer covers the other's
territory.

## Whatever's gone quiet for a month

A skill that hasn't fired in a month isn't helping answer anything
anymore — it's just one more description in the pile Claude has to sort
through. Turn it off. Nothing gets erased: it can come back the day the
need does.

## The overload signal

There's no magic number. But past roughly 10–15 enabled skills, expect
the wrong one to answer once in a while — that's a signal, not a rule.
Some teams run twenty active skills just fine, because each one covers
clean territory. The real test is the symptoms, not the count:

- **The wrong skill answers** — the reply doesn't match what you expected
  from that sentence.
- **A skill never fires** — you know it's there, but nothing triggers it,
  even when the situation looks built for it.
- **Two skills answer the same request**, one after another or at
  different times, for the same kind of question.

Any one of these is reason enough to take a closer look at the roster.
